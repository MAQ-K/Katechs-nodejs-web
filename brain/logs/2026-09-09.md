### The navigator now has three shapes, not two
`SectionNav` took a `floating` boolean; it now takes **`mode`: "inline" | "bar" | "rail"**. Same
component, same items, same active state - a different shape. Rail = fixed to the physical LEFT
edge, vertically centred, 16px inset: the same edge and inset `/services`' `.wsv-rail` uses, so the
site's two rails agree.

**Why not framer-motion FLIP.** A row cannot transition into a column - `flex-direction` is not
animatable. FLIP was the obvious tool and was rejected on purpose: framer's layout projection
re-measures against the viewport, and the only thing that triggers this morph is the user
scrolling. A layout animation whose measurements move while it runs is its documented failure
case, and "no layout jumps in both directions" was the hard requirement. Instead: the FLIGHT is a
pure transform (both fixed modes share `top:0/left:0` and differ ONLY in transform, so one
interpolates into the other), the capsule's shape transitions alongside it, and the
flex-direction flip is masked by a staggered settle on the items. Two keyframe NAMES, one per
mode - a shared name would not restart and the swap would snap.

**The one-frame gate.** Pinning and "web services covers the viewport" go true in the same frame,
which would take the nav straight from static to a fixed rail with no previous transform to
interpolate from. `wasPinned` forces one frame of `bar` first. That frame is invisible because
`bar` sits exactly where the slot just pinned.

**Rail membership is a midline test** (`section.top <= vh/2 <= section.bottom`), not a top-edge
test: symmetric, so it flips at the same place going down and coming back up.

**No layout jump, two mechanisms:** the slot keeps reserving the nav's height in BOTH fixed modes
(releasing it in rail mode would yank the page up ~62px mid-morph), and the screen reserves the
rail's gutter ALWAYS, not on arrival. The space the rail frees is freed inside the viewport, not
out of the document - which is what lets `scrollTo` drop the reserved-bar term for a
`data-fullscreen` section and land it flush at the top.

🔴 **RTL trap, cost me a bug:** the gutter was first written `padding-inline-start`. This page is
`dir="rtl"`, so that reserved space on the RIGHT while the rail stands on the physical LEFT. The
rail is positioned physically (`left:0` + `translate3d(16px,...)`), so its gutter must be physical
`padding-left` too. Anything positioned physically needs physical spacing to match.

### The morph was rebuilt - "make the animation smoother its bad now"
v1 animated only the FLIGHT. The capsule's width and height were never transitioned, so the box
snapped 614x58 -> 150x268 in one frame while it flew, and the items hard-cut from row to column
under a 0.15-opacity flicker. Everything moved except the shape change itself, which is the part the
eye watches.

v2 is a three-phase choreography: contents fade out (130ms, box still), shape swaps behind them
while the box tweens width/height/radius/position together (430ms), contents fade back in from
300ms. Both fixed modes carry EXPLICIT width/height - `max-content` cannot be tweened, and that
omission is exactly why v1 snapped.

**Three bugs found by measuring, not by looking:**
1. 🔴 **The contents stayed invisible forever.** The morph effect had `shape` in its dependency
   array, so the swap timer setting `shape` re-ran the effect, whose cleanup cancelled the un-dim
   timer that had not fired yet. Fixed by reading the previous shape from a ref so the effect
   depends on `mode` alone. Sampling opacity over time caught this in one run; it is invisible to a
   static screenshot.
2. **inline -> rail snapped** with no tween. A transition needs a value to start FROM, and `inline`
   is in normal flow with `width: auto` - there is nothing to leave behind. Now a `bar` frame is
   planted and given two rAFs (one guarantees style computation, two guarantee a rendered frame)
   before the morph starts. This is the click-a-nav-pill and fast-flick path.
3. **rail -> inline shoved the page.** `inline` is in FLOW, so tweening the capsule's height down
   from 268px there resized a real box and moved everything below it. A morph is only safe while the
   element is out of flow: bar<->rail morphs, anything touching `inline` is instant.

Measured, sampling geometry every 25ms: **18 distinct interpolated frames** entering, a continuous
curve leaving, 1 (instant, correct) for the fast-flick reset.
