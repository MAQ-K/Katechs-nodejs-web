### 6. Why choose us — the box-switcher (real redesign, not a tweak)

content a screen reader or no-JS reader gets, so nothing is ever announced twice. Same call the old

the stacked single-column layout there's no such sibling, so `.hp-why-stage` is `display: none` and

### A measurement lesson worth keeping

Every fetched page in this session is a **single-line** SSR response (`wc -l` = 0). `grep -c` counts
matching LINES, so on a single-line file it can only ever report 0 or 1 — it silently collapses any
real count ≥2 down to 1. Caught this once today (an app-orbit skeleton check read "1" when the real
count was 6) before it was reported as a finding; re-verified with `grep -o ... | wc -l`. **Every
verification in this log that mattered used either `grep -o | wc -l` or real browser DOM queries
(`querySelectorAll().length`, `getComputedStyle()`) — never a bare `grep -c` on fetched HTML for a
count that could exceed 1.**

## Homepage hero — bug fix: text rendering dark instead of white

User report: "the font color — make them light" (hero text appearing dark). Root cause found,
not a simple color tweak.

### The bug
The design pass wrapped `.hp-hero-text` and its children in `motion.div` / `motion.h1` / `motion.p`
for the staggered entrance. styled-jsx only auto-attaches its compiled scope class to elements it
sees as a literal lowercase JSX tag in that file — a `motion.*` call is a component reference, not
a host element, so it never got the scope class. Every rule targeting that subtree
(`.hp-hero-text`, `.hp-hero-eyebrow`, `.hp-hero-text h1`, `.hp-hero-lead`, `.hp-hero-actions`, and
the CTA button rules chained off `.hp-hero-actions`) was silently matching nothing. The visible
result: the headline/eyebrow/paragraph fell through to `style.scss`'s global
`h1,h2,...{ color: $heading-color }` (`#212121`, near-black) instead of this file's white — dark
text on a dark video, unreadable. This is the exact same class of bug the file already documents
