## UI Implementer — widened the area/section spacing ratio

User: "i feel like the margin between areas are the same". Checked the served markup first — the
values were applying correctly (56px section / 120px area), so this was not a bug. **2:1 simply does
not read as a different kind of break** when the surrounding content blocks are 180px tall; the eye
needs a much larger multiple before it groups things.

Widened to ~4:1 and made both scale with the viewport so the area gap doesn't turn into a dead band
on a phone:

| | before | after |
|---|---|---|
| `$wsv-gap-section` | `56px` | `clamp(32px, 4vw, 48px)` |
| `$wsv-gap-area` | `120px` | `clamp(110px, 14vw, 200px)` |

Also removed the `.wsv-nav` padding override in the ≤767px block — it was hard-coded 36/70px and
would have collapsed the area break back to section size on mobile, defeating the clamp.

**Lesson worth keeping:** when a spacing ratio "feels the same", check the served values before
touching anything — then fix it by widening the ratio, not by nudging one number.
