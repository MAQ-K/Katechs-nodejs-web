## Area 1 — section 2 (الباقات / packages)

`components/Services/BusinessWebsites/Plans.js` + `businessWebsites.{plansSection,pricing}`.

**Decisions taken with the user:**
- **Prices with an EG/SA currency switch** (the `data/hosting-services/data.js` shape), not
  app-development's quote-based `priceLabel`. Toggle is local `useState`, no routing.
- **Static navy highlight** on the recommended tier, **not** AppDev's rotating conic border beam
  (`.app-plan-beam`). This page already carries a moving hero and a moving carousel; the beam would
  be the third moving thing in one viewport.

**Grid is based on `.seo-grid`/`.seo-plan`, not AppDev's Bootstrap row** — real CSS grid
(3-up → 2-up at 991 → 1-up at 575), `height: 100%` equalises cards for free, and the badge sits in
flow (`align-self: flex-start`) instead of being an absolutely-positioned corner tag, so there is
nothing to mirror in RTL. Avoids AppDev's `.app-pricing-row > [class*="col-"] { display: flex }`
Bootstrap workaround entirely.

**🔴 PRICES ARE PLACEHOLDER.** Every `price` is `"—"` with a `priceNote: "TODO(prices)"`. Six figures
(3 tiers × 2 currencies) are needed from the business. Published prices are a commitment to
customers and were not inferred. Note also: the SA figures must be genuinely SA — the hosting page
has a standing bug where its ر.س tier is still priced in ج.م (`data/hosting-services/data.js:98`)
and that must not be repeated here.

**Register: MSA, not the hosting page's Egyptian colloquial.** Hosting says "اختار باقتك" /
"اللي تناسب أعمالك" / "الاكثر طلبا"; app-development and seo say "اختر نطاق مشروعك" /
"الأكثر طلبًا". A corporate-websites buyer is the app-development audience, so this section takes
that register. Badge uses the MSA spelling `الأكثر طلبًا` (the codebase contains both).

**Ladder is scope, not feature-count** (the AppDev device): موقع تعريفي → موقع شركة كامل (popular)
→ موقع + متجر. Each tier repeats a cumulative "كل ما في الباقة السابقة" line (borrowed from
`components/Seo/Pricing.js`) so the three read as one ladder, and each ends on a support line —
direction.md motive 4, "don't make this project painful". Cards name concrete deliverables because
this block carries the proof burden the cut portfolio/process sections would have carried.

**Traps avoided:**
- `is-popular`, never `popular` — confirmed `style.scss:3326` is a global unscoped `.popular` with
  `background-color: red` + `transform: rotate(45deg)` + physical `right: -50px`. Verified in the
  served markup: the only matching class is `wsv-plan is-popular`.
- Card hover lift is `whileHover={{ y: -6 }}` in JS, not CSS — framer-motion writes an inline
  transform on the card and a CSS `transform` would lose to it. Only the shadow changes in SCSS.
- Feature `li` uses `align-items: flex-start` + icon `flex-shrink: 0` + icon `margin-top: 4px` so a
  wrapped Arabic item keeps its tick on the first line. Deliberately **no** `min-height`: nothing in
  this system has one, and it would mask uneven copy rather than fix it. `flex: 1 1 auto` on the
  list + `margin-top: auto` on the CTA keeps the buttons level across cards.
- The grid is keyed on the currency so flipping it re-keys and fades the cards; without that the
  numbers swap in place with no acknowledgement.

**Verification:** `/services/` 200; clean `npx sass`; all new selectors in the compiled `style.css`;
badge/heading/tier/cumulative-line strings present in the served HTML; both currency labels render;
no new dev-server errors.

**Lock:** claimed and released around the SCSS write.
