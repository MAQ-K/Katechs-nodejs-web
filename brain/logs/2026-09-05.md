### The RTL order trap — got it wrong first, measured, fixed
`grid` + `order` to put the carousel left. **In RTL the flow starts at the right edge, so the LOWER
order value sits on the RIGHT** — the opposite of the LTR intuition. First attempt used the LTR
reading and put the carousel on the right; the measurement caught it (`railLeft: 740` vs
`textLeft: 45`). Now text `order:1` (right), stage `order:2` (left) — verified `railLeft: 45`,
`textLeft: 740`. The reasoning is in the component so the next person does not re-derive it.

### What vertical did and did not inherit from the horizontal marquee
- **Not inherited:** `ProjectsMarquee`'s `direction: ltr` workaround. That bug is specific to the
  INLINE axis (a max-content flex track hanging off the RTL container's right edge). `direction`
  does not affect block-axis layout, so a column track needs no override. Deliberately left out.
- **Inherited:** margin-on-the-item rather than flex `gap` (N items have only N-1 gaps, so a gapped
  track is not exactly N copies and the seam drifts), pinned 4/3 `aspect-ratio` (stops track height
  changing as images load), and the mask-not-overlay fade.
- **COPIES = 2, not 3.** Same rule (one copy ≥ the visible window) but the horizontal one had to
  survive a viewport *wider* than one copy — a real screen size. Here the window is a height we set
  (560px) against a 2921px copy, so 2 is safe.
